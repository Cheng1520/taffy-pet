# 塔菲桌宠

把立绘抠出来放在桌面上。点一下她会说「关注塔菲喵关注塔菲谢谢喵」，同时弹出发音和
DeepSeek 账户余额，并蹦一下；平时会自己慢慢呼吸。

只有一张立绘，所有动态都是程序化变换做出来的，不需要额外的序列帧素材。

## 跑起来

```bash
pip install -r requirements.txt
python main.py
```

## 操作

| 动作 | 效果 |
| --- | --- |
| 左键点击 | 说话 + 弹余额 + 播音效 + 蹦一下 |
| 左键拖动 | 挪位置（松手后记住，下次启动还在那） |
| 右键点她 | 菜单：设置 API Key / 刷新余额 / 眨眼 / 窗口置顶 / 退出 |

右键要**点在她身上**。窗口是无边框透明的，周围有一圈看不见的透明边距（见下面
「窗口边距是个权衡」），那圈里右键也能出菜单，但从外面看不出来，所以首次运行会
自动弹一次操作提示。

拖拽和点击按位移量区分（超过 6px 算拖拽），所以想挪位置不会误触发说话。

## 配置 API Key

两种方式，环境变量优先：

1. 环境变量 —— 设 `DEEPSEEK_API_KEY`（推荐，Key 不落盘）
2. 右键「设置 API Key」，粘进输入框，存到 `config.json`

`config.json` 已经在 `.gitignore` 里。**Key 不会被提交。**

### 调大小

`config.json` 里的 `height` 是**角色在屏幕上的高度**，默认 200，单位是「逻辑像素」
（和 Qt 的窗口坐标同一套单位，会跟着 Windows 缩放比例走）。你屏幕是 200% 缩放，
所以 200 逻辑像素 = 屏幕上 400 物理像素 ≈ 整屏高度的四分之一。觉得大了小了改这个数就行。

其余配置项（音量、透明度、默认位置等）也都在 `config.json`，删掉该文件会恢复默认值。

## 重新生成素材

素材已经生成好了，正常跑桌宠不需要这一步。改了原图才需要：

```bash
python tools/build_assets.py
```

从原始立绘产出 `assets/taffy.png`（抠图）、`assets/taffy_blink.png`（闭眼帧）、
`assets/eyes.json`。

音效来自录屏视频，重新提取：

```bash
python tools/extract_audio.py <视频路径> click
```

## 实现上的几个坑

这些都踩过，写下来省得下次再踩。

### 抠图不能用「到白色的距离」

浅粉头发 `(251,183,184)` 到白色的距离约 101，而 JPEG 灰噪声能到 90 —— 两者数值重叠，
调容差必然二选一：要么留下灰噪声，要么把呆毛和发辫整个吃掉（实测 tol=100 吃掉 15%
浅粉像素，呆毛直接没了）。

改用**彩度 `max-min`** 区分：灰噪声彩度 ≈ 0-5，粉发彩度 = 68，干净分开。
再配合「只保留和边框连通的背景块」，被角色包住的白色区域（比如袖口内侧）就不会被误删。

判据见 `tools/build_assets.py`，探针脚本的历史结论在 `tools/_blink_explore.py` 顶部。

### 闭眼帧的填充方式（踩了四个坑才找对）

闭眼帧是离线生成的：把原眼睛涂掉，再画一道睫毛弧。

难点在眼睛上方那条窄缝，夹在深色刘海和眼线之间。**一开始用 `cv2.inpaint`，
它从上下左右各方向取色，上方就是深色刘海，发色被带下来，在右眼上方抹出一块灰。**
后面换的三种办法都是在这个思路里打转，所以都没解决：

| 试过的办法 | 结果 |
| --- | --- |
| 朝肤色基准拉回 | 能淡掉，但要压平区域，退回「平涂补丁」的老错误 |
| 收紧掩膜护栏 | 更糟 —— 护栏把掩膜上缘切出硬边，灰块反而变大 |
| 按闭眼线上下镜像 | 左眼干净了，右眼那块灰仍在 |
| **逐行横向插值** | **解决了** |

正解是换掉取色方向：**只在同一行内，用被遮段左右两侧的像素做线性插值，永远不往上取。**
同一行左右两侧是刚出掩膜的干净皮肤，从根上避开发色。

副作用是相邻行接不上、出现横向条带，所以后面补一道纵向高斯 —— 但必须用
**归一化卷积**（只在掩膜内加权平均）。直接模糊的话，掩膜上缘会把上面的刘海又吸进来，
等于绕一圈回到原来的问题。

护栏纵向取 1.75 也是量出来的：1.55 时右眼上方留着原图上睫毛的残影，
扩到 1.95 以上就会啃掉刘海 —— 发丝轮廓是高对比的，缺一块比多一道睫毛线更扎眼。

### 弹跳用关键帧，不用弹簧

先写的弹簧（欠阻尼，点击给一个速度冲量）。问题是阻尼会把回弹那一侧吃掉：
压扁 5%，拉伸只剩 1%，看着是「沉了一下」而不是跳起来。

改成关键帧后压扁/腾空/落地分开写，每档幅度能算准，也能在测试里断言。

### 尺寸：高 DPI 屏上差点整只跑到屏幕外

资源是 800px 高的高分辨率图，最早是按 1:1 画出去的，想着「反正资源就是显示尺寸」。
但在 200% 缩放的屏上，1 个逻辑像素 = 2 个物理像素，于是 800 逻辑像素 = 1600 物理像素
—— 正好占满整块屏，头还被顶到屏幕上方，看着像「程序根本没启动」。用户就是这么报的。

修法是让资源像素和显示尺寸彻底脱钩：`config.json` 的 `height`（逻辑像素）决定画多大，
`pet.py` 按比例缩放。资源分辨率只影响清晰度，不影响大小。

连带的：**动画里所有量都必须是比例，不能有写死的像素**。同一个错误还在腾空高度上犯了
第二次 —— `HOP` 本来是写死的 12px，角色从 760px 缩到 200px 之后这一跳的相对高度翻了
三倍，呆毛直接被窗口顶边裁掉。现在 `HOP` 是「占角色高度的比例」。

### 窗口边距是个权衡

拉伸会让角色向上长高，长多少就得在窗口里预留多少透明边距，否则呆毛会被窗口顶边裁掉。
但边距同时也是窗口挡住周围桌面图标的面，所以不能随便加大。

边距取角色高度的 6.5%（`pet.py` 的 `MARGIN_RATIO`）：呼吸 0.8% + 弹跳拉伸 3.0% +
腾空 1.6% = 5.4%，留了余量。这个比例同样是量出来的，`tools/smoke.py` 会走完整条弹跳
曲线验证不溢出，并断言压扁幅度 ≥5%。

## 自检

```bash
python tools/smoke.py
```

起窗口、截几张图（`assets/_smoke*.png`）、验证边界与幅度、检查菜单能否构建，然后退出。
不用盯着屏幕也能看出渲染和变换对不对。

## 结构

```
main.py                  入口
taffy_pet/
  config.py              配置读写、API Key 优先级
  balance.py             查 DeepSeek 余额（放在线程里，不冻界面）
  toast.py               气泡：说话 + 余额共用一个窗口
  anim.py                呼吸、点击弹跳、眨眼
  pet.py                 主窗口：透明无边框置顶、拖动、右键菜单
tools/
  build_assets.py        抠图 + 眼睛定位 + 闭眼帧
  extract_audio.py       从录屏提取音效
  smoke.py               冒烟测试
  _blink_explore.py      闭眼帧的探索记录（含失败史）
```
