# 实现笔记：踩过的坑

改代码之前值得看一眼。每条都是真踩过、真花时间的，尤其闭眼帧那条 —— 前三种做法
看着都合理，全失败了。

## 抠图不能用「到白色的距离」

原图是白底，直觉上「离白色够远就是角色」应该能行，实际不行：

浅粉头发 `(251,183,184)` 到白色的距离约 **101**，而 JPEG 灰噪声能到 **90** —— 两者数值
重叠。调容差必然二选一：要么留下灰噪声，要么把呆毛和发辫整个吃掉（实测 tol=100 时
吃掉 15% 浅粉像素，呆毛直接没了）。

改用**彩度 `chroma = max-min`** 区分：灰噪声彩度 ≈ 0-5，粉发彩度 = 68，干净分开。
再配合「只保留和图像边框连通的背景块」，被角色包住的白色区域（比如袖口内侧）就不会被误删。

判据见 `tools/build_assets.py` 的 `build_cutout()`，探针脚本的历史结论在
`tools/_blink_explore.py` 顶部。

## 闭眼帧的填充方式（踩了四个坑才找对）

闭眼帧是离线生成的：把原眼睛涂掉，再补一道睫毛弧。难点在眼睛上方那条窄缝 —— 它夹在
深色刘海和眼线之间，既要填干净，又不能把刘海带下来。

**第一版用 `cv2.inpaint`，它从上下左右各个方向取色，上方就是深色刘海，发色被带下来，
在右眼上方抹出一块灰。** 后面换的三个办法都是在这个思路里打转，所以都没解决：

| 试过的办法 | 结果 |
| --- | --- |
| 朝肤色基准拉回 | 能淡掉，但要压平区域，等于退回「平涂补丁」的老错误 |
| 收紧掩膜护栏 | **更糟** —— 护栏把掩膜上缘切出硬边，灰块反而变大 |
| 按闭眼线上下镜像 | 左眼干净了，右眼那块灰仍在 |
| **逐行横向插值** | **解决了** |

正解是换掉取色方向：**只在同一行内，用被遮段左右两侧的像素做线性插值，永远不往上取。**
同一行左右两侧是刚出掩膜的干净皮肤，从根上避开发色。

副作用是逐行独立插值会让相邻行接不上、出现横向条带，所以后面补一道纵向高斯 —— 但必须用
**归一化卷积**（`blur(rgb*w) / blur(w)`，只在掩膜内加权平均）。直接模糊的话，掩膜上缘会把
上面的刘海又吸进来，等于绕一圈回到原来的问题。

护栏纵向取 `1.75` 也是量出来的：`1.55` 时右眼上方留着原图上睫毛的残影（在显示尺寸下看得见
一道深色痕），扩到 `1.95` 以上就会啃掉刘海 —— 发丝轮廓是高对比的，缺一块比多一道睫毛线更扎眼。

## 弹跳用关键帧，不用弹簧

先写的弹簧（欠阻尼，点击给一个速度冲量）。问题是**阻尼会把回弹那一侧吃掉**：压扁 5%，
拉伸只剩 1%，看着是「沉了一下」而不是跳起来。

改成关键帧（`anim.py` 的 `BOUNCE_KEYS`）之后，压扁／腾空／落地分开写，每档幅度能算准，
也能在测试里断言。

拉伸峰值刻意压在 1.03：拉伸会让角色向上长高，长多少就要在窗口里预留多少透明边距，
而边距越大，窗口挡住周围桌面图标的面就越大。压扁到 0.93 才是主视觉，而它是**变小**，不占边距。

## 尺寸：高 DPI 屏上差点整只跑到屏幕外

素材是 800px 高的高分辨率图，最早按 1:1 画出去，想着「反正素材就是显示尺寸」。但在
200% 缩放的屏上 1 个逻辑像素 = 2 个物理像素，于是 800 逻辑像素 = **1600 物理像素**，
正好占满整块屏，头还被顶到屏幕上方 —— 看着像「程序根本没启动」。

修法是让素材像素和显示尺寸彻底脱钩：`config.json` 的 `height`（逻辑像素）决定画多大，
`pet.py` 按比例缩放。素材分辨率只影响清晰度，不影响大小。

连带的教训：**动画里所有量都必须是比例，不能有写死的像素。** 同一个错误在腾空高度上犯了
第二次 —— `HOP` 本来是写死的 12px，角色从 760px 缩到 200px 之后这一跳的相对高度翻了三倍，
呆毛直接被窗口顶边裁掉。现在 `HOP` 是「占角色高度的比例」（`anim.py`）。

## 窗口边距是个权衡

拉伸会让角色向上长高，长多少就得在窗口里预留多少透明边距，否则呆毛会被窗口顶边裁掉。

**曾经以为边距的代价是「挡住周围桌面图标的面」，实测不是。** 窗口是带 alpha 的 layered
window（`WS_EX_LAYERED`），透明像素点得穿 —— `WindowFromPoint` 打在透明边距上返回的是
下层窗口，打在她身上才返回自己这个窗口。所以边距几乎不花什么代价，够用就行。

边距取角色高度的 6.5%（`pet.py` 的 `MARGIN_RATIO`）：呼吸 0.8% + 弹跳拉伸 3.0% + 腾空 1.6%
= 5.4%，留了余量。这个比例同样是量出来的 —— `tools/smoke.py` 会走完整条弹跳曲线验证不溢出，
并断言压扁幅度 ≥5%。
