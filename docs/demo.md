# 演示视频是怎么录的

README 顶上那段 [`taffy-demo.mp4`](https://github.com/Cheng1520/taffy-pet/releases/download/v1.0.0/taffy-demo.mp4)
不是录屏，是**渲染**出来的。这份笔记说明为什么这么做、它跟真程序差在哪、
以及想自己重出一遍该怎么做。

## 跑一遍

```bash
python tools\demo.py            # 出一整支，约 47 秒
python tools\demo.py --still 31 # 只出第 31 秒那一张 PNG，用来对着看排版
```

产物落在 `_work\demo\`（`/_work/` 在 `.gitignore` 里，不会进版本库）。
整支跑完大约 15 秒 —— 比实时快得多，因为不需要等网络也不需要等时钟。

## 为什么不用录屏

要求是**白底**。这台机器的桌面不是白的，录屏会把壁纸、任务栏、别的窗口一起录进去，
那是**隐私**不是演示；现成的录屏工具也没有「只录一个窗口、顺便把背景换成纯白」
这种能力。

换一条路就顺了：桌宠本来就是 Qt 画的，那就让 Qt 把每一帧画到一张白底画布上，
再交给 ffmpeg 编码。于是

- 背景是纯白，跟桌面上有什么完全无关；
- **一个窗口都不弹**（`WA_DontShowOnScreen`），录的时候不用把机器空出来；
- 可重放：同一份素材每次跑出来一模一样，不像录屏会被系统动画和通知弹窗搅了。

编码走 `imageio_ffmpeg` 自带的那支 ffmpeg（`requirements.txt` 里本来就有），
不用另装东西。

## 它跟真程序差在哪

用的**全是真控件**：`PetWindow`、`Toast`、`ChatWindow` 都是生产代码，
立绘、影子、朝向、气泡、呼吸、眨眼、弹跳、跳舞、聊天窗的排版一点没改。差的是两样：

| | 真程序 | 演示 |
| --- | --- | --- |
| 动画时钟 | `QTimer` 每 20ms 走一格 | 停掉定时器，按帧号手动拨 |
| 聊天的内容 | DeepSeek 流式吐字 | 脚本按时序喂进去 |

**朝向那一段是个例外，得手动拨**：她跟着鼠标转，而渲染时鼠标在哪跟片子无关。
所以演示里那一帧的朝向是钉住的，读起来像「她在朝某个方向看」——真机上它跟着
你的鼠标走。

**弹跳的时长不写死在演示脚本里**，走 `anim.BOUNCE_MS`：改了关键帧曲线，片子跟着走，
不用回来改第二个地方。（这个项目已经在「同一个换算写了两遍」上栽过一次 ——
`state()` 和 `bounce_curve()` 的位移换算不一致，见
[implementation-notes.md](implementation-notes.md)。）

**时钟**必须钉死：25fps 的片子要的是确定的那一帧，靠真实时钟就会漂。

**聊天**不连 DeepSeek，一是要花钱、二是同一句话每次回得都不一样，片子就没法重录。
但喂进去的路径是真的 —— 走 `ChatWindow._append_widget` / `_add_trace`，
跟流式回复落地时调用的是同一对方法，所以画出来的东西和真聊一遍没有区别。

**「现在几点？」和「记住我爱熬夜」两行小字是真调出来的**：`agent.run("now", …)`
和 `agent.run("remember", …)`，跟真程序走同一个函数。只是把表拨死了
（`DEMO_NOW`），因为录制那一刻的真实时间戳没有理由跟着视频发到 GitHub 上；
顺带整支片子变成可重放的。`remember` 会写文件，所以事先把 `MEMORY_PATH`
指到了临时目录。

## 数据安全

`tools/demo.py` **绝不碰**用户的任何真实数据。开工前先做三件事（见 `_isolate()`）：

1. `chat_store.CHAT_PATH` / `memory.MEMORY_PATH` 指到临时目录；
2. `config.save` / `chat_store.save` 换成空函数；
3. 配置用一份现造的字面量 `DEMO_CFG`，里面**没有 `api_key`**。

第 2 条不是加固，是必需的：`ChatWindow.closeEvent` 里有 `cfgmod.save(self.cfg)`，
不隔离的话光是把演示窗口关掉就会把那份假配置覆盖到真的 `config.json` 上。
而源码运行时 `paths.DATA_DIR` 就是项目根目录 —— 那正是用户 Key 所在的地方。

余额那一行（`余额 ¥42.00`）是编的，不是任何人的真实余额。

## 时间轴

改脚本时对着这张表改。总长 47 秒。

| 起 | 止 | 内容 |
| --- | --- | --- |
| 0.0 | 4.0 | 标题卡 |
| 4.0 | 7.0 | 待机：呼吸、眨眼，跟着鼠标左右转头 |
| 7.0 | 13.0 | 没人理她自己动了：蹦一下 + 冒出「塔菲在看着你哦。」 |
| 13.0 | 19.0 | 点她一下：弹跳 + 气泡说话 + 报余额 |
| 19.0 | 25.5 | 跳舞，跳两遍 |
| 25.5 | 43.5 | 聊天窗：三来三回，中间两次工具调用 |
| 43.5 | 47.0 | 结尾卡 |

聊天那一段的时序单独写在 `_chat_script()` 里，`[(本地秒, 事件), …]`，
四种事件：`you`（我说）/ `dots`（她进入「…」打字态）/ `trace`（挂一行工具轨迹）/
`say`（她的话，字一个个长出来）。

**画布是写死的 1280×720，所以字号一律用 `setPixelSize` 不用点。** 点会跟着系统
DPI 走，第一版标题和副标题直接叠在一起了。

## 声音

语音库那 20 条 wav 是 24kHz 单声道 16bit，直接按采样点相加混成一条全长音轨
（不用 ffmpeg 的 `amix` —— 总共就五段，按采样点加更直白也更容易看出「什么时候该响」）。
落在哪几秒写在 `main()` 的 `clips` 里，跟画面上的动作对齐。

五段分别是：她自己找事做时说的（`14.wav`，就是画面上那句「塔菲在看着你哦。」）、
点她之后（`01.wav`）、跳舞时（`03.wav`）、记事那条轨迹之后（`18.wav`）、
以及她说「累了就早点休息喵」（`13.wav`）。
